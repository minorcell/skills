# 已知坑

动手前先读一遍。这些不是理论风险，是这条管线实际踩过的。

## 1. 终端里的汉字渲染成空方块

**这是最容易漏的一个。** Menlo、SF Mono、Monaco、Consolas、DejaVu Sans Mono——三大平台的纯等宽字体几乎**都不含中文字形**。终端演示里写 `git add 完成首页布局.py`，汉字会渲染成 `□□□`。

Pillow 不会报错，`getlength()` 也返回正常数值，**只有把图渲染出来看才发现**。

解决：终端文字一律走 `fonts.py` 的 `draw_mono()`，它把字符串切成 ASCII / 汉字分段，ASCII 用等宽字体、汉字用中文字体，并让每个汉字正好占两个 ASCII 格宽（等宽终端里汉字本来就是两格）。

不要直接对终端文字调 `d.text()`。不要用 `f.getlength("汉字") > 0` 来判断字体是否含中文——缺字形时也会返回非零宽度。

判断字体真含中文的可靠办法在 `fonts.py` 的 `has_cjk()`：比较汉字与私用区码位 `` 的渲染 mask，或看两个不同汉字的 mask 是否相同（相同 = 都是同一个豆腐块）。

## 2. 配音和画面长度天然不等 → 长时间静止

画面代码按名义时间写（`t > 5.8` 出现某元素），配音按句读。12 分钟的片子，配音比动画时间轴长 2-3 倍很常见。直接渲染会导致每场画面提前搭完、然后静止 20 多秒——观众以为视频卡了。

**验证方法**：算每场的「最大静止间隔」和「尾部静止」，超过 3-4 秒就要调。当时有场戏尾部静止 23 秒。

三层解决，缺一不可：
- `timing.py` 把动画节点锚到句子节拍，并按场景时长调整构建窗口。
- 终端打字动画独立按真实时长铺满（`Terminal.draw` 里的 `SCENE_REAL_DUR` 分支）。
- 节点数远少于句子数时，均匀铺满整段而不是挤在开头。

**注意**：解析动画节点时，只做源码正则**不够**——循环里生成的节点（`reveal(t, 0.6 + i * 0.75)`）只能看到字面量 `0.6`。必须在 `t=1e6` 处干跑一次场景函数，把 `reveal()` 实际收到的 `start` 全录下来（`knots_of()` 的做法）。

## 3. 字幕漂移

按「字数比例」分配每句时长会累积漂移——中文里标点、数字、英文词的朗读速度完全不同。

edge-tts 的 `SentenceBoundary` 事件带精确的 `offset`/`duration`，直接用它。只有在本地 TTS 兜底（拿不到时间戳）时才退回比例估算。

字幕时间还要加上开场留白：第 i 场的配音开始时刻 = 前面所有场的 `LEAD + 配音时长 + TAIL` 之和，再加本场的 `LEAD`。

## 4. 渲染超时 / 后台进程被杀

12 分钟成片约 2.3 万帧，1080p 约 29ms/帧。**顺序渲染总计 12-15 分钟。**

### 分块跑 / 看住后台

- 全量渲染在单次 bash 调用里可能撞 600s 超时，稳妥起见分两批。
- 后台进程可能在 bash 调用结束时被一起杀掉。用 `run_in_background: true`，
  然后 `ps aux | grep render` 确认还活着再等。
- 每场渲染完立即落盘 mp4，中途挂了只需重跑缺的场次（场景过滤参数）。

## 5. edge-tts 报 403

`WSServerHandshakeError: 403, Invalid response status`。

**先升级**：`pip install -U edge-tts`。微软会迁移语音端点，旧版本连不上旧端点。2026-10 那次端点从 `speech.platform.bing.com` 迁到 `api.msedgeservices.com`，靠升级到 7.3.1 解决。

**不要**只加重试——端点变了，重试一百次也是 403。也**不要**自己去拼 `Sec-MS-GEC` 和 websocket 握手参数，版本号对不上反而更难排查。

**不要交付本地 TTS 的音频。** macOS `say`、Linux `espeak` 音色机械，只够自己预览。

## 6. 版面重叠

逐帧生成画面的通病，而且**必然发生**：你算好了位置，但文字长度随内容变化。

高频位置：
- 卡片上的标签压到卡片或副标题（两个元素各自居中，行高不同就撞上）。
- 终端最后一行压到页脚。
- 底部字幕条压到画面主体。
- 长英文词组不换行冲出边框（`wrap()` 要保留西文单词完整）。

办法只有一个：**每场渲染 45% 和 90% 两个进度点的定格图，拼成 contact sheet，逐张看。** 用 Read 工具真的看图，不要靠代码断言布局正确。当时 16 场戏里揪出 6 处重叠，全是看图看出来的。

## 7. 进度条与全局时钟

顶部进度条按「已配音时长 / 总时长」算。如果按场景序号算，短场和长场的进度推进速度会明显不匀。

## 8. 章节标题的时刻

简介和视频里的时间戳要对得上。章节开始时刻 = 该场之前的累积时长 + `LEAD`，不是「该场配音开始」也不是「该场画面开始」。差 1 秒在时间轴上看起来就是错的。

## 9. 手绘主题的两个陷阱

- **抖动必须按 seed 确定。** 用全局 `random` 会让同一帧在不同调用里产生不同抖动，成片闪烁。`theme.py` 里所有抖动都走 `_rng(salt)`。
- **抖动是低频的。** 逐点随机噪声看起来像信号干扰，不像手绘。做法是两三个正弦波叠加 + 端点外延。抖动幅度 2-3px 够了，超过 5px 会显得脏。

## 10. 页眉品牌名写死在模板里（换主题必踩）

`engine.py` 的 `header()` 里曾经硬编码了模板主题的品牌标记：

```python
d.text((56, 40), "GIT", font=font(21, "b", mono=True), fill=ORANGE)
```

换主题时这里**不会报错**，只会安静地把旧主题的名字印在每一帧的左上角。
后果很严重：成片全部导出、字幕做完、封面做完之后，才发现每一帧都印着
上一个主题的品牌名，只能**全量重渲**。

**已修**：`engine.BRAND` 是可以被覆盖的模块级变量，`scenes.setup()` 会从
`content.py` 读 `BRAND` 写进去。新主题只要在 `content.py` 里写一行：

```python
BRAND = "XXX"        # 页眉左侧的标记，用 ASCII（走等宽字体）
```

**动手前自查**：`grep -n '"GIT"\|"flat"\|"handdrawn"' scripts/engine.py scripts/scenes.py`
——模板里任何写死的主题相关字面量都要在开工时先清掉。

## 11. 解说词漏一个逗号 → 元组 → TTS 报 `text must be str`

多行字符串靠**相邻字面量自动拼接**，不写逗号也能连起来。但漏掉中间某一行的逗号，
那两行就变成**元组**，前面的行是个字符串：

```python
narration=(
    "第一段。"          # ← 漏了这个逗号
    "第二段。"          # 加上这个逗号，前两行就成了 tuple
    "第三段。"
)
# 结果 narration 是 ('第一段。第二段。', '第三段。')
```

`edge-tts` 直接报 `TypeError: text must be str`，重试 4 次全失败，然后**静默回落到本地
`say`**（音色机械，不能交付）。

**防御**：写完 `content.py` 立刻跑一次断言，比渲染完才发现便宜得多。

```bash
python3 -c "
import sys
sys.path.insert(0, 'scripts')
from project import configure_source
configure_source()
from content import SCENES
for sc in SCENES:
    assert isinstance(sc['narration'], str), (sc['sid'], type(sc['narration']))
print('解说词全部是字符串 ✓', len(SCENES), '场')"
```

渲染和字幕生成前也要验证 `SCENES` 的数据类型，避免错误在后续步骤才暴露。

## 12. 别把 AIGC 标注忘了

配音是 AI 合成的，平台对 AIGC 内容有标识要求。发布文案里要提醒用户勾选平台声明或在简介注明。这不是可选项。
