# 视频制作包

从「一个主题」到「一包能直接发布的交付物」。核心是**用代码生成画面**，不是录屏、不是套模板：画面由 Python 逐帧绘制，配音由 TTS 合成，两者按句子节拍对齐。

## 交付物（四件，缺一不可）

| 交付物 | 规格 | 生成方式 |
|---|---|---|
| 成片 | 1920×1080 / 30fps / H.264 / AAC 立体声 | `render.py` → `build_final.py` |
| 封面 | 1146×717（B 站 16:10），另出 1280×720 备用 | `covers.py` |
| 字幕 | SRT（UTF-8，毫秒精度） | `make_srt.py` |
| 发布信息 | 标题 / 简介 / 标签 / 分区 / 发布时间 | Markdown，见 `reference/publish.md` |

字幕曾经是被漏掉的那一件——它必须在流程里显式产出，不能只在对话里给一段文字。

## 第一步：提问（不要跳过）

主题从来不是需求。开工前必须问清下面这几项，**一次问完**，然后才动手。用 `AskUserQuestion`，每题 3-4 个选项，把推荐项排在第一个。

必问的四面：

1. **交付形态** —— 带配音的成片 / 只出画面+字幕 / 动画网页 / 幻灯片+讲稿。默认推荐带配音的成片。
2. **时长与深度** —— 3 分钟极简 / 8-12 分钟完整教程 / 20 分钟以上系列。时长决定分镜数量，必须先定。
3. **受众** —— 完全零基础 / 有一点基础 / 从业者。这决定用不用生活化比喻、术语密度。
4. **画面风格** —— `flat`（米白纸底+圆角卡片，信息密度高，适合命令演示、流程讲解）或 `handdrawn`（Anthropic 编辑部手绘风：暖色平涂底+象牙承载+近黑墨线，留白大、比喻强，适合概念与心智模型）。见下节。

可问可不问（拿不准就问）：平台（决定封面比例与标题字数规则）、配音音色（女声/男声/沉静）。

**问完要复述一遍再开工**，一句话确认：「8-12 分钟完整教程，面向零基础，手绘风，发 B 站，晓晓配音——按这个来。」

## 第二步：风格选择

风格在 `scripts/theme.py` 里是两个主题字典，绘制代码只读主题、不写死颜色。切换主题不改任何场景代码：

```python
from theme import get_theme
T = get_theme("handdrawn")     # 或 "flat"
T["paper"], T["ink"], T["accent"]
```

- **flat** —— 米白 `#F6F2EA` 底、白卡片、圆角 22px、柔和投影、橙红 `#F05133` 强调。适合信息密度高、要放终端和代码的画面。
- **handdrawn** —— 陶土 `#D97757` 满铺底、象牙 `#FAF9F5` 承载形状、近黑 `#141413` 手绘墨线。禁渐变、禁投影、禁高光，全程平涂。暖灰一律带黄褐底调，不用冷蓝灰。

手绘风的三条硬规则（写在 `theme.py` 的注释里，改之前先读）：

1. **线要粗、端点要圆、走向要轻微不匀。** 抖动是低频的（两三个正弦波叠加），不是逐点噪声——逐点噪声像信号干扰，低频扰动才像手绘。几何完美的手绘是假的。
2. **平涂。** 不用渐变、不用投影、不用高光、不用 3D。
3. **一帧只讲一个比喻**，形状有意不对称。标题强调用手绘下划线而不是色块。

主题方法：`hand_path` / `hand_rect` / `hand_round_rect` / `hand_blob` / `hand_arrow` / `hand_underline` / `scribble` / `card`。
抖动是**按 seed 确定的**——同一帧重复绘制结果必须一致，否则成片会闪烁。

## 第三步：写脚本（content.py）

分镜脚本是唯一的内容源，**解说词驱动画面时长**（不是先定画面再塞词）。

```python
VOICE = "zh-CN-XiaoxiaoNeural"
RATE  = "+8%"
SCENES = [
    dict(sid="s01_hook", chapter=None, render="hook", narration="……"),
    dict(sid="s02_what", chapter="一 · 什么是版本控制", render="savepoint", narration="……"),
]
```

每个场景三样东西：`sid`（唯一标识，配音文件名）、`chapter`（章节标签，`None` 表示不显示）、`render`（画面对应 `scenes.py` 里 `RENDERERS` 的一个键）、`narration`（解说词）。

写作要求：

- 每段解说词 30-60 秒，对应**一屏画面**。句子要短，句末用 `。！？`——切句粒度直接决定字幕和画面节拍。
- 结构：痛点开场 → 概念 → 原理 → 实操 → 回顾。第 1 场必须是"你可能经历过的场面"，最后一场必须是对整集的收束。
- 讲概念用生活比喻，但**比喻只用一个，贯穿始终**（购物车、存档点）。换比喻等于让观众重新学习。
- 术语第一次出现要给解释，官方译名如果比俗称难懂就用俗称，并在讲稿里说明取舍。

## 第四步：配音与时间戳

```bash
python3 scripts/tts.py            # 先自检，确认能出声
python3 -c "from tts import generate; from content import SCENES; generate(SCENES, '/tmp/audio')"
```

edge-tts 的 `SentenceBoundary` 事件给出**逐句精确时间戳**，字幕和画面节拍都由它驱动。这比按字数比例估算准得多——当时那版视频用的是比例估算，字幕会有累积漂移。

⚠️ **edge-tts 会因微软端点调整而报 403。** 2026-10 那次是靠升级到 7.3.1 修好的。遇到 403 先 `pip install -U edge-tts`，光重试没有用。本地引擎（macOS `say`）只作最后兜底，音色机械，**不要交付**。

## 第五步：画面与配音对齐（timing.py）

这是整条管线里最容易做错的一环。

画面代码写的是**名义时间**（`t > 5.8` 出现某元素），配音是逐句读的，两者长度天然不等。`timing.py` 把名义节点锚到句子节拍上：

- 解析场景函数里的动画节点（源码正则 + 在 `t=∞` 处干跑一次，捕获循环里生成的节点）。
- 把节点映射到句子开始时刻；节点数少于句子数时，均匀铺满整段。
- 把整组锚点压进时长的 `[3%, 62%]` 窗口——画面在前三分之二搭好，之后完整画面陪讲。否则元素稀稀拉拉拖到最后一秒，中间大片空白。
- 终端打字动画**独立于**场景 warp，按真实时长铺满整场（`TERMINAL_FILL = 0.90`）。

改完必须验证：`最大静止间隔` 和 `尾部静止` 都不该超过 3-4 秒。长静止 = 观众以为视频卡了。

## 第六步：渲染与合成

```bash
python3 scripts/render.py /tmp/durs.json /tmp/vid all   # 逐帧渲染，直接管道给 ffmpeg
python3 scripts/build_final.py /path/to/final.mp4       # 与配音合成，加淡入淡出
```

- 逐帧渲染**直接 pipe 给 ffmpeg**，不落盘 PNG（12 分钟视频约 2.3 万帧，落盘会很慢）。
- 每场 `LEAD 0.30s` + 配音 + `TAIL 0.70s`，场景间有呼吸感。
- 性能参考：1080p 单帧约 29ms。12 分钟成片渲染约 12-15 分钟，**分块跑**，单次 bash 调用会超时。

## 第七步：验收（不许省）

交付前逐项过：

1. **看完所有场景的定格图**。每场取 45% 和 90% 两个进度点，拼成 contact sheet 逐张看。
   看三件事：文字溢出边框、元素重叠、汉字是不是方块。**关键帧必须用 Read 工具真的看图**，不能只靠代码断言。
2. `ffprobe` 校验：1920×1080、30fps、h264、立体声、时长。
3. **音频连续性**：`silencedetect=noise=-50dB:d=1.0`，静音段只应出现在章节之间。
4. **字幕与配音对齐**：抽查开头/中段/结尾三处，字幕文字与当刻配音一致。
5. **封面缩略图测试**：缩到 300px 宽看还认不认得出主标题。

## 第八步：交付

产出到工作目录，文件命名带上内容标题：

```
<主题>.mp4             成片
<主题>.srt             字幕
<主题>-封面.png        封面
<主题>-发布文案.md     标题/简介/标签/分区/发布时间
<主题>-source/         全部源码（脚本、引擎、合成）
```

交付时说明：时长、分辨率、内容结构、**刻意的取舍**（哪些地方为了受众放弃了准确术语）、以及源码怎么改（改 `content.py` 的解说词重跑即可，画面节拍会自动重算）。

## 依赖

```
ffmpeg（含 ffprobe）  pillow  edge-tts
```

中文字体由 `scripts/fonts.py` 自动探测（Linux Noto Sans CJK / macOS Hiragino Sans GB / Windows 微软雅黑），找不到会明确报错告诉你怎么装。
**等宽字体在三大平台上几乎都不含中文字形**——终端里的汉字会变成空方块，这是最容易忽略的坑。`fonts.py` 的 `draw_mono()` 做中英分段混排解决它，终端文字一律走它，不要直接调 `d.text()`。
